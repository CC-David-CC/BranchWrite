# Literal-file teaching and repair

New coding roots whose live schema grants create_file receive three additional
worked examples. Existing roots/controllers stay frozen. Context creation still
uses the canonical COW input history. No native operator, sampler, grammar rule,
capability type or workflow ledger changes.

The examples demonstrate nested creation, exact Unicode and literal dollar text,
LF/CRLF and absent final newline, actual file readback, and correction of unwanted
indentation. The third example has an explicit edit grant. A create grant never
permits overwriting an existing file. Real tool feedback and no-overwrite checks
remain authoritative; examples cannot grant paths or tools.

Build them from owned synthetic tasks with:
    PYTHONPATH=. python scripts/build_literal_file_examples.py --output examples/literal-file-worked-examples.txt

The builder invokes actual ToolRegistry/Executor operations. Observation world
identities belong to that temporary run, so regenerated text gets a new prefix
identity. The tests replay actions in independently created worlds and check
actual output bytes, dispositions, current read observations and untouched files.
This CPU evidence is not model, GPU, restart or numerical qualification.

Why: original protected Ubuntu L02 finished unverified. The model inserted one
space at the start of line two; the actual file tool preserved its proposal.
It subsequently recognized and honestly reported the mismatch. The fixture
granted creation/readback but no editing, so correction was impossible. Repeated
creation was rejected and the bounded loop exhausted. The reference, task and
checker remain unchanged. The model error and restrictive task grant are distinct.

The new prefill contains no protected L02 answer or path. Its actual model effect
