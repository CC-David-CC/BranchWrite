# Preserve an unverified terminal workflow without calling it a lesson

BW can now archive a closed coding program whose recorded workflow verdict is
explicitly false, even when it edited files without running a current check.
It validates the actual host/program binding, baseline, settled supported tool
outcomes, closed model frames and original COW receipts. It never reconstructs
unchecked file history or claims that the resulting source is correct or wrong.

```sh
python -m branchwrite lesson capture-terminal-failure /owned/run --output /owned/new-failure-archive
python -m branchwrite lesson terminal-show /owned/new-failure-archive
```

These commands are local and read-only with respect to the original run. They
make no model, tool, network or training requests. A BW read lease excludes a
concurrent workflow writer. The bounded private archive copies launch, ledger
and native-journal bytes and pins the validator/helper implementation. It
remains readable after the original world and server are unavailable. It does
not include mutable world files, numerical checkpoint caches or model weights.
The observer's own source hash is pinned even when an owner explicitly loads
it outside a preserved old BW source tree for read-only diagnosis.

Open or unsettled workflows, verified successes, unsupported local outcomes,
external effects and unproven terminal isolation remain refused. This archive
is not a failure/correction lesson capture and cannot approve training. To teach
a correction, separately produce fresh owned practice, execute its checks and
use the verified-practice pathway. Protected diagnostic tasks remain excluded.

S3's workflow evaluator and explicit recovery helper use this evidence for a
proven closed false attempt: workflow finished=false, passed=false, artifact
correctness unassessed. An unavailable or unsettled boundary remains an
infrastructure failure. The other cases in the panel can continue; the evidence
is not turned into a fabricated independent artifact grade.

The [qualification](evidence/terminal-workflow-failure-20261026.json) records
26 BW controls, 13 S3 integration/recovery controls, and read-only diagnosis of
one actual MiniCPM attempt. That trace contains 16 reads, 15 applied text-file
replacements and 32 native receipt frames; it closed without a verified finish.
The original evaluator refusal, ledger and native journals remain unchanged.
No failed model question, training update or tool effect was replayed.

This fixes evidence handling, not the model's tendency to keep editing. The
complete joined native learning round is still unfinished. Old archives keep
their original validator source identities; installing a new reader does not
silently migrate their policy, scores or release status.
