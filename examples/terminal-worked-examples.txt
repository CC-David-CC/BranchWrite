TERMINAL WORKED EXAMPLES
========================
These are separate synthetic teaching tasks. Their raw command results were
collected using the real read-only terminal sandbox on Linux. The final reports
are host-authored examples of how to describe those results, not claims that a
model generated them. Timing, operation IDs and private world identities are
omitted from the teaching excerpts; exact raw receipts remain in build evidence.
These examples grant no paths, executables or permissions. The current task's
tool schema and host grant are authoritative.

A printed success message cannot override the real exit status.
Keep drafting notes out of the final answer.
Refer to the first or second probe when repeating a command is unnecessary.
Use enough private thinking to understand the observations, then provide a clean
final tool action. Do not paste tentative alternatives into its answer string.
Do not recopy whole scripts unless the current user explicitly asks for them.
Each completed probe needs its own actual status and both output streams.
If a typo was corrected, state the original error and corrected observation.
Never invent tool output, infer success from source alone, or hide a failed
attempt behind a later successful command. Do not change intentional failures.

A finish action requests completion; it does not certify the task by itself.
File readback proves file bytes and visible reads, not semantic report quality.
Grammar constraints ensure framing, not truth. The final report must still
cover the actual request, preserve distinctions and use the observed evidence.
