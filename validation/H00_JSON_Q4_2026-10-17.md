# H00 with model-output JSON Schema: bounded PASS

On llm-60, one real Q4 generation through BranchWrite's machine CLI, COW HTTP
and native GPU worker produced a schema-constrained `create_file` action. The
host independently validated it, exercised the existing exact create/read grants,
and read back `Hello, loop.` followed by LF: 13 bytes. The unchanged supplied H00
checker passed. There was one proposal and no repair or hidden model retry.

Created/read-back SHA-256:
`3c9684133d84aa9fd70b0e61911712040fa1dd994f4fd223ec7053ec8adf1a39`.

The selected schema requires tool, arguments, path and string content. It admits
only `create_file` and the host-authorized path; content remains unconstrained
task work rather than an encoded answer. The host also rejects duplicate keys,
extra fields, wrong types/tools/paths and oversized content. No action runs before
consumed EOS. Grammar does not confer permissions.

This opt-in H00 experiment does not replace BranchWrite's canonical v0.6 workflow
language. Existing coding tasks still use `.bw` TEXT. The host performs read-back
after the model's create proposal; this does not claim autonomous multi-turn tool
selection. It does not establish H01 browser capture, H02 image delivery, broader
agent capability, numerical restart equivalence, VC00-VC09 or G1-G5 qualification.
