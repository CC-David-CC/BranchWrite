# Start here

For the current private Context COW work, read
[`docs/COW_INTEGRATION_PLAN.md`](docs/COW_INTEGRATION_PLAN.md) alongside this
handoff. It records current capabilities, pending seed/stop integration and the
first client/sampler experiment. Historical native CLI references are not the
current capability inventory.

1. Open the user's actual BenchWrite checkout. Read its instructions, verify origin,
   revision, dirty state, baseline tests and license. An unread repository is not empty.
   Keep this handoff beside it; do not extract over the root or overwrite owner files.
2. Read the v0.6 specification. v0.4/v0.5 and the original ZIP are immutable provenance,
   not alternative active specifications. Read the migration before porting case names.
3. Run this bundle's offline checks. They need only Python 3.11+ standard library and
   make no native, SSH, network or process-execution claims.
4. Discover the installed native COW source/CLI and its actual controls through existing
   authorized local access. Bind `configs/native.unbound.toml` privately. Never invent
   paths, fields, sampler implementations, device capacities or a model deployment.
5. Implement the dependency graph in `acceptance/tickets.toml`. Build the single-branch
   nested session and real child-return recovery early, then branch grammar/sampler
   isolation and true overlapping ACT work through the same interpreter.
6. Qualify each sampler separately. The first useful runtime needs constrained greedy
   and the available stochastic baseline, not every experimental sampler. No requested
   control may be silently ignored or replaced by another one.
7. Retain source-bound evidence, failures, unqualified capabilities and unresolved work.
   Produce a runnable CLI and real campaign report in the user's actual repository.

No global installation, destructive Git command, shared-service restart, weight download,
credential dump, public push or deployment is authorized by this handoff. Existing
ordinary scoped grants may be used; wider actions require the owner's real authorization.

Commands here are handoff commands. Product examples describe the proposed language;
there is no claim the installed `branchwrite` already implements it.
